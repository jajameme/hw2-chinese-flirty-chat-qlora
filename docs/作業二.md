# 作業二實作紀錄：土味情話多輪對話專家（QLoRA）

日期：2026-10-25。依 [`plan/作業二實作計畫：土味情話多輪對話專家（QLoRA）.md`](../plan/作業二實作計畫：土味情話多輪對話專家（QLoRA）.md) 開始實作。計畫中關於模型、資料與繳交的文字是規劃依據；本文件只記錄實際完成與實測的部分。

## 實作範圍

專案位於 [`hw2_flirty_chat/`](../README.md)，改寫課堂 [`cases/llm_finetune`](https://github.com/telunyang/python_nlp/tree/main/cases/llm_finetune) 的 4-bit QLoRA 流程。程式共用一份固定的繁體中文 system prompt，基礎模型使用 `Qwen/Qwen2.5-0.5B-Instruct`。本次先建立本機可重現的資料、訓練、推論與比較流程；後續已由使用者指定獨立 GitHub 倉庫 jajameme/hw2-chinese-flirty-chat-qlora，並授權將本次實作與成果推送至該倉庫。

## 實作方式與過程

1. **環境。**在 `hw2_flirty_chat/.venv` 建立 Python 3.12 虛擬環境，先安裝 CUDA 12.8 版 PyTorch，再安裝 `requirements-training.txt` 固定的 Transformers、TRL、PEFT、bitsandbytes、datasets、accelerate、Matplotlib、OpenCC，最後將完整環境寫入 `requirements.txt`。虛擬環境、HF 模型快取及暫存 checkpoint 已由 `.gitignore` 排除。
2. **候選語料。**[`make_raw.py`](../make_raw.py) 撰寫 17 個情境 × 每情境 10 組原創梗。每組有第一輪回覆、使用者追問及接續回覆，再以兩種開場展開為 `raw/*.json`，共 340 段、每段兩輪。170 個獨立梗各展開兩次。情境含初識、告白、約會、道歉、吃醋、早晚安、下雨、節日、考試、職場、遠距、被拒絕、忙碌、日常、冷笑話與心情低落。
3. **資料驗證與正規化。**[`build_corpus.py`](../build_corpus.py) 檢查每段至少兩輪、`user → assistant` 交替、內容非空，以第一個 user 訊息去重；加入完全相同的 system prompt，並以 OpenCC `s2twp` 轉繁體，輸出 `data/chat.jsonl`。
4. **人工審核入口。**[`data/review.csv`](../data/review.csv) 每個梗一列，`approved` 空白表示尚待人工審核。填入 `yes`／`no` 後可用 `python build_corpus.py --approved-only` 只匯出通過的梗。這批候選語料是 AI 撰寫，**目前沒有人工逐筆審核**；本次訓練是流程驗證版，不能稱為已通過人工篩選的最終語料。
5. **切分與展開。**[`prepare_chat_data.py`](../prepare_chat_data.py) 先把共用相同答案的兩種開場綁在同一組，以 seed 42 分組切分，再展開每個 assistant 回覆為 prompt/completion。保留固定 system prompt 和最近六則上下文；避免同一梗的答案同時出現在訓練與驗證集。
6. **QLoRA。**[`train_qlora.py`](../train_qlora.py) 使用 NF4、double quantization、FP16 compute、rank 8／alpha 16／dropout 0.05 的 all-linear LoRA，只學 assistant completion。序列上限 512、batch 4、累積 4、最多 3 epochs、`paged_adamw_8bit`、每 15 optimizer steps 評估與儲存，依 validation loss 選最佳 checkpoint，patience 3 提早停止。對 1660 Ti 不使用 BF16，且在建立 SFTTrainer 後再次確認可訓練參數為 FP32。
7. **推論與評估。**[`infer_lora_chat.py`](../infer_lora_chat.py) 保留多輪歷史、輸出轉繁體；[`compare_base.py`](../compare_base.py) 用五組同題兩輪問題比較基礎模型與 LoRA，另產生五輪接梗展示；[`plot_loss.py`](../plot_loss.py) 從訓練紀錄畫 loss 曲線；[`render_demo.py`](../render_demo.py) 把實際五輪輸出排版為圖片，明確標記為逐字稿排版圖。

初次執行訓練時，`SFTConfig` 拒絕 `warmup_ratio`：安裝的版本需使用 `warmup_steps`。已改為由預估總步數計算 5% warmup steps，並重新執行。這是實際相容性修正，非計畫原先的設定。

重跑後，前 15 steps 完成首次評估：train loss 約 3.651、validation loss 約 3.686。第 15 步紀錄一次 `grad_norm=nan`，但 loss 有限；第 20 步 `grad_norm` 恢復約 3.262，train loss 約 3.450。將以後續評估判斷是否有持續的數值不穩定。儲存 checkpoint 時 PEFT 嘗試連網找模型 config，被本機網路設定拒絕並發出警告；這次 checkpoint 儲存仍可繼續。

完整訓練後，後續梯度範數均回到有限值，沒有再出現 `nan` loss。validation loss 從第 15 步的 3.686 降到第 75 步的 3.2388，之後在第 90、105 和 117 步約為 3.242、3.254、3.255；相對於繼續下降的 training loss，顯示後期已有輕微過擬合。最終採用第 75 步，而非最後一步。曲線見 [loss_curve.png](../images/loss_curve.png)。

以相同五組開場與追問做貪婪解碼，結果見 [comparison.md](../results/comparison.md)。0.5B 微調版的語氣較短、較溫和，但未穩定達到「延續上一輪梗」：例如天文館追問「星星看不清楚」時回答轉到工作休息；道歉情境的回覆也不夠具體。原始模型同樣有答非所問或重複題目的情況。五輪展示的後三輪仍能維持對話形式，但笑點偏弱，見 [逐字稿排版圖](../images/demo_chat.png)。因此 **0.5B 完成了技術流程，尚不能視為合格的多輪情話專家**。依計畫接著測試 1.5B。

1.5B 的 `check_gpu.py --model-size 1.5b` 已成功：NF4 載入並生成回覆，PyTorch 推論峰值約 1.10 GiB。訓練腳本新增 `--model-size 1.5b`，使用獨立的 `outputs/flirty_lora_15b/`、batch 1、gradient accumulation 8、gradient checkpointing；1.5B 的 trainable LoRA 參數為 9,232,384。起始全卡顯存約 4.9 GiB（含其他行程），每個 optimizer step 實測約 30 秒。會以第一個 validation 結果決定是否繼續完整三個 epoch。

使用者要求改成背景執行並以 `state.json` 查完成狀態。為此新增 [`run_background.py`](../run_background.py)：啟動時尋找最新完整 checkpoint，接續訓練，再自動執行 loss 圖、模型對照與五輪逐字稿圖片；每 5 秒原子更新狀態檔，記錄 `status`、`stage`、目前步數、最佳驗證 loss、子程序 PID、日誌及完成產物。若任一步驟失敗，會寫入 `failed` 和錯誤尾端；全部成功才寫 `completed`。使用方法見專案 [README](../README.md#15b-第二輪)。

2026-10-25 16:55（台北時間）已啟動隱藏背景程序，從完整的 **checkpoint-75** 接續 1.5B 訓練；該 checkpoint 的 validation loss 為 **2.7629**，預估總步數 231。背景程序使用本機已下載的模型快取，並保留 checkpoint 的 optimizer、scheduler 與隨機數狀態。`hw2_flirty_chat/state.json` 是查詢入口；`updated_at` 使用 UTC（`+00:00`），台北時間加 8 小時。完成訓練後會依序產生圖表與對照，確認所有產物存在，並自動在本文件附上完成結果。程式加入作業系統檔案鎖，避免重複啟動兩份背景流程。

## 重現步驟

在專案目錄執行（完整安裝說明見 [README](../README.md)）：

```powershell
python make_raw.py
python build_corpus.py
python prepare_chat_data.py
python check_gpu.py
python train_qlora.py
python plot_loss.py
python compare_base.py
python render_demo.py
python infer_lora_chat.py
```

模型首次下載需要網路。若重新執行 `make_raw.py`，只有 seed ID 與內容雜湊都相同的審核決定會保留。人工審核後須重新建立語料、切分並訓練；尚未審核前不要把本次結果當作最終品質結論。
